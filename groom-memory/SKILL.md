# /groom-memory

Memory holds in-context principles, pointers to wherever canonical state actually lives, and reference cards for traps worth recognizing twice. It does not hold tracker state, long-form design docs, or session narrative — those belong elsewhere, or nowhere, and duplicating them is the drift.

Cut more than you add. Memo count grows when writes outpace consolidation, so collapse the clusters where one lesson has been restated in fresh vocabulary across several files, drop entries for closed work, and replace whatever duplicates an external tracker with a single index entry: project and milestone IDs plus the recipes to query live state.

Deletes are irreversible and memory shapes vary by project. Ask rather than guess, impose no fixed structure, and judge the result by how fast future-you picks up — not by how much is written down.
